# ComputePilot v0.2 实施计划

> **依据**: 论文 *"From Research Question to Scientific Workflow: Leveraging Agentic AI for Science Automation"* (2604.21910.pdf) 的四 Agent 架构
>
> **v0.1 定位**: 确定性运行时（DAG/执行器/状态/复现）—— **已完成并发布 v0.1.0**
>
> **v0.2 定位**: 论文的"管道编排层"—— 从科研问题到可执行 DAG 的智能翻译

---

## 目标架构（对齐论文）

```
用户 (科研人员)
   │  自然语言研究问题
   ▼
Conductor            ← 多轮对话、领域路由、澄清/纠错、审批门
   │
   ▼
Workflow Composer    ← 意图提取(LLM+Skill)、规划、DAG 生成
   │
   ▼
Deterministic Runtime（v0.1 已有：Engine/Scheduler/Executors）
   │
   ▼
Execution Sentinel   ← 监控、异常检测、进度反馈
```

---

## 六个模块任务

### M1 — Skill 格式升级（知识层, v0.1 有雏形）

扩展 `Skill` 模型为论文的三要素文档：

```yaml
name: population_genetics
vocabulary_mappings:        # 词汇映射
  population:
    european: EUR
    african: AFR
    east_asian: EAS
  region:
    chromosome_1: chr1
parameter_constraints:      # 参数约束
  chromosomes:
    allowed: ["1", "2", ..., "22", "X"]
    required: true
  populations:
    min_items: 1
    max_items: 5
optimization_strategies:    # 优化策略
  selective_data_extraction: true
  parallelism_autotune: true
```

**交付物**：
- `Skill.vocabulary_mappings` / `parameter_constraints` / `optimization_strategies` 字段
- `Skill.resolve_vocabulary(token) -> code`
- Skill YAML 文档加载 + 校验
- 测试：词汇解析、约束校验

### M2 — VocabularyResolver（词汇解析器）

将自然语言 token 规范化为领域编码：

```python
resolver = VocabularyResolver(registry)
resolver.resolve("european population on chromosome 1")
# → {"population": "EUR", "region": "chr1"}
```

**交付物**：
- `agent/vocabulary.py` — VocabularyResolver
- 正则/分词 + Skill 词汇表匹配
- 多 token 组合解析
- 未匹配 token 收集 → 进入 Conductor 澄清流程
- 测试

### M3 — Conductor（编排者）

论文的 Conductor = 用户入口 + 多轮对话 + 路由 + 审批门：

```python
session = Conductor(registry, planner, provider)
# 第 1 轮
resp = session.turn("Run population comparison between European and African on chr 22")
# → 缺: analysis_type → 返回澄清请求 {"missing": ["analysis_type"]}
# 第 2 轮
resp = session.turn("comparison of all variants")
# → 完整 Intent {analysis_type: comparison, ...} → Workflow plan + 描述
```

**交付物**：
- `agent/conductor.py` — Conductor session（状态机）
- ChatSession：多轮上下文累积
- `fill missing fields` 澄清循环
- 审批门（复用 PolicyEngine）
- `cpilot plan --interactive` CLI
- 测试：澄清循环 ≤ 3 轮

### M4 — Deferred Generation（延迟生成）

论文关键创新：先探测环境→测量真实数据大小/CPU→再生成最终 DAG。

```
Phase 1: 计划（估计值）
Phase 2: 探测（数据大小、可用 vCPU）
Phase 3: 最终 DAG（基于真实测量）
```

**交付物**：
- `runtime/probe.py` — EnvironmentProbe（数据大小、vCPU、内存）
- `Planner.plan(intent, probe_result)` — 支持探测反馈
- `Engine.run(..., deferred=True)` — 两阶段执行
- 测试：探测→生成→执行闭环

### M5 — Execution Sentinel（执行哨兵）

论文的监控 + 异常检测 + 反馈闭环：

**交付物**：
- `runtime/sentinel.py` — 监控任务进度
- 异常聚合（停滞任务、重复失败）→ Diagnoser
- 进度报告 → Conductor（用于多轮反馈）
- `cpilot status --live` 实时监控（可选）
- 测试

### M6 — Skill 示例：population_genetics

按论文的 1000 Genomes 用例造一个真实领域技能：

- 词汇映射（population/region codes）
- 参数约束（chromosomes allowed list）
- 优化策略（selective data extraction）
- 集成测试：Resolver + Conductor + Deferred 全链路

## 优先级与里程碑

| 阶段 | 模块 | 周期 | 验收标准 |
|---|---|---|---|
| **P0-A** | M1 Skill 升级 | 1 周 | Skill 词汇/约束/策略字段 + resolve_vocabulary |
| **P0-B** | M2 VocabularyResolver | 1 周 | 自然语言→领域编码，未匹配→澄清 |
| **P1-A** | M3 Conductor | 2 周 | 多轮澄清循环 ≤ 3 轮；`cpilot plan --interactive` |
| **P1-B** | M4 Deferred Generation | 2 周 | 探测→最终 DAG 闭环 |
| **P2** | M5 Execution Sentinel | 2 周 | 监控+异常聚合→诊断反馈 |
| **P2** | M6 population_genetics | 1 周 | 端到端 Demo 5（论文 1000 Genomes） |

**总周期**: ~ 9 周
