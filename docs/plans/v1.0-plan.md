# ComputePilot v1.0 规划

> **方向**: 组合与稳定化 — 工作流 include 复用、运行态 DAG 可视化，达成 1.0 发布标准

---

## 背景

迈向 1.0 的两块最后拼图：
1. 科学工作流常有公共前置步骤（数据获取/环境准备）——目前只能复制粘贴任务定义
2. 运行中的 DAG 只能在 Dashboard 看 SVG；CLI 侧无法对**已持久化的运行**做依赖图检查

## 目标

### 1. 🧩 工作流 include 组合（P0）

```yaml
# main.yaml
name: full_pipeline
includes:
  - common/prep.yaml        # 相对路径；可嵌套
tasks:
  - id: analyze
    command: python analyze.py
    depends_on: [prep_data]  # 引用 include 提供的任务
```

- 递归解析（include 的 include），相对各自文件定位
- 循环 include → 报错；任务 id 冲突 → 报错列出冲突项
- 合并发生在模型构建前，validator 看到的是完整任务集

### 2. 📊 `cpilot dag --run <run_id>`（P0）

- 从 state.db 读取持久化的 workflow 结构（v0.5 起保存）渲染
- ascii 格式标注每个任务状态：`✓ gen [shell, succeeded]`
- svg 格式节点按状态着色（复用 svgdag）

### 3. 🏷️ 1.0 发布工程（P1）

- `computepilot.__version__` 导出 + pyproject classifiers/keywords 完善
- e2e Demo 5：参数化 → 双次运行 → `cpilot verify` 可复现判定

### 4. 🔒 API 稳定承诺（P1）

- docs/api-stability.md：公开面（CLI 命令、computepilot.api 函数签名、workflow YAML schema）
  自 1.0 起语义化版本，破坏性变更需升 major

## 验收

| 项 | 标准 |
|---|---|
| include | 嵌套合并单测；循环/重名报错；e2e 用例跑通组合工作流 |
| dag --run | 有运行数据时三格式输出正确；无结构数据的旧运行给出明确提示 |
| 发布工程 | __version__ == pyproject 版本；Demo 5 进 CI |
