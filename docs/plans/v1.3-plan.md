# ComputePilot v1.3 规划

> **方向**: 调度与运维 — 任务优先级、Prometheus 指标、模板脚手架

---

## 背景

- 并发槽位有限时，就绪任务的执行顺序完全取决于 YAML 书写顺序——关键路径任务无法插队
- 运营方需要标准指标端点接入 Prometheus/Grafana，而不是爬 HTML
- 新用户起步要翻 examples 目录复制文件

## 目标

### 1. 🎯 任务优先级（P0）

```yaml
tasks:
  - id: critical_path
    priority: 10        # 默认 0，越大越先调度
  - id: background
    priority: -5
```

- `Task.priority` 可选字段（向后兼容）；并发槽位竞争时按
  `(-priority, 拓扑序)` 排序截取
- `cpilot dag --format json` 输出 priority

### 2. 📈 `/metrics` Prometheus 端点（P0）

```
GET /metrics
# TYPE computepilot_runs_total counter
computepilot_runs_total{status="succeeded"} 12
# TYPE computepilot_tasks_total counter
computepilot_tasks_total{status="failed"} 3
computepilot_artifacts_total 41
```

- 文本 exposition 格式；无 DB 时全部为零值

### 3. 🧰 `cpilot init --template`（P1）

```bash
cpilot init my_exp --template parameter_sweep
```

- 内置模板：hello_world / parameter_sweep(foreach) / ml_pipeline / docker_worker
- 模板内嵌代码（pip 安装后同样可用），不再依赖仓库 examples/

### 4. 📄 `cpilot status --json`（P1）

- 无 RUN_ID → 运行列表 JSON；有 RUN_ID → 详情 JSON（与 /api/run/{id} 同构）

## 验收

| 项 | 标准 |
|---|---|
| 优先级 | 并发=1 时执行顺序按 priority 降序；默认 0 不改变现有行为 |
| metrics | TestClient 校验 HELP/TYPE 行与计数正确性 |
| init --template | 四模板可生成且通过 validate |
