# ComputePilot v1.1 规划

> **方向**: 表达力与韧性 — 原生参数扫描、优雅中断

---

## 背景

- 科学计算最常见的模式是**同一任务的参数扫描**——目前必须让 Agent 生成 N 个任务或手写重复 YAML
- 运行中按 Ctrl-C 直接砸掉事件循环：运行状态悬在 RUNNING，无法干净地 resume

## 目标

### 1. 🔁 `foreach` 任务扇出（P0）

```yaml
name: sweep
tasks:
  - id: simulate
    foreach:
      values: [10, 20, 30]      # 可含 ${params}
      as: item                  # 展开变量名
    command: python sim.py --n ${item}
    resources:
      cpu: ${cores:-4}
```

等价于三个任务 `simulate_0/1/2`。语义：

- 加载期展开（merge includes → 参数替换 → foreach 展开 → 校验）
- 每个值生成独立任务，id 为 `<base>_<index>`
- `as` 变量在该任务所有字符串字段中替换（command/args/env/inputs/outputs）
- 其他任务 `depends_on: [simulate]` 自动重写为依赖全部展开实例
- 上限 500 实例，超出报错

### 2. 🛑 `cpilot run` 优雅中断（P0）

- Ctrl-C 不再裸崩：捕获 KeyboardInterrupt → 运行标记 CANCELLED → 提示 resume 命令 → exit 130
- 已完成任务保持持久化，`cpilot resume <run-id>` 续跑剩余任务

### 3. 📄 `cpilot logs --json`（P1）

- 结构化输出事件数组，供脚本消费

### 4. 🎛️ Dashboard 运行列表状态过滤（P1）

- `/` 页顶部状态筛选按钮（all/running/succeeded/failed），纯前端实现

## 验收

| 项 | 标准 |
|---|---|
| foreach | 展开/嵌套 include/depends_on 重写/上限 单测；e2e 扇出运行成功 |
| 中断 | 模拟 KeyboardInterrupt 后状态为 CANCELLED、exit 130、resume 成功 |
