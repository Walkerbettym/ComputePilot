# ComputePilot v1.4 规划

> **方向**: 进程安全与通知 — 孤儿进程治理、并发写安全、失败回调

---

## 背景

- `cpilot cancel` 只翻转数据库状态——**正在执行的子进程成为孤儿**继续烧 CPU
- WAL 已启用但未设 `busy_timeout`，CLI 与 Dashboard 并发写会立刻抛 `database is locked`
- 长跑任务失败无人知晓，只能人肉轮询 status

## 目标

### 1. 🔪 `cpilot cancel --kill`（P0）

- 引擎 submit 后记录 `process_started` 事件（payload 含 pid）
- `cancel --kill`：对 RUNNING 任务取最近 pid → SIGTERM → 0.5s 存活则 SIGKILL → 再标记 CANCELLED
- 不加 --kill 保持旧行为（仅改状态），向后兼容

### 2. 🔐 并发写安全（P0）

- StateStore 连接统一 `PRAGMA busy_timeout=5000`
- 并发集成测试：双连接同时写入不抛 locked 异常

### 3. 📣 失败/完成 Webhook（P1）

```yaml
name: wf
notifications:
  on_failure:
    url: https://hooks.example.com/cpilot
    timeout: 5        # 秒，可选
```

- 引擎到达终态后 fire POST JSON：
  `{event: run_failed|run_succeeded, run_id, workflow, status}`
- 失败静默（suppress 一切异常），不影响运行本身退出码

## 验收

| 项 | 标准 |
|---|---|
| cancel --kill | 单测：真实 sleep 子进程被终止；DB 状态 CANCELLED |
| busy_timeout | pragma 值断言 + 双连接并发写通过 |
| webhook | 本地 HTTP server 收到正确 JSON payload |
