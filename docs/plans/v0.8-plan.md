# ComputePilot v0.8 规划

> **方向**: 参数化与运维 — 工作流模板参数、运行数据生命周期管理

---

## 背景

科学计算工作流的两大现实需求：
1. 同一工作流反复跑不同参数（扫描/调参）——目前只能复制粘贴 YAML
2. 运行数据无限累积——SQLite 与 runs/ 目录没有清理入口

## 目标

### 1. 🔧 工作流参数化（P0）

```yaml
# workflow.yaml
tasks:
  - id: train
    command: python train.py --epochs ${epochs} --lr ${lr}
    environment:
      DATA: ${dataset:-default.csv}     # 支持默认值
```

```bash
cpilot run wf.yaml --set epochs=50 --set lr=0.01
cpilot validate wf.yaml --set epochs=50      # 校验前先替换
```

- 占位符语法：`${key}` 必填、`${key:-default}` 带默认值
- 替换范围：command / args / environment 值 / inputs / outputs
- 未提供的必填参数 → 明确报错列出缺失项（exit 2）
- 替换发生在校验之前，资源规则看到的是最终值

### 2. 🧹 `cpilot runs clean`（P0）

```bash
cpilot runs clean --days 30          # 删除 30 天前的运行记录 + 磁盘目录
cpilot runs clean --dry-run          # 预览将删除的内容
```

- 清理范围：runs / task_states / task_events / artifacts / approvals 五表 + runs/<id> 目录
- 终态保护：仅清理 SUCCEEDED/FAILED/CANCELLED 的终态运行

### 3. 📡 Dashboard 实时事件页（P1）

- `/run/{id}/live` — 轮询 `/api/run/{id}/events` 游标，追加式事件流

### 4. 🛠️ `cpilot skill new <name>`（P1）

- 生成技能 YAML 脚手架（含 vocabulary/constraints/error_handling 注释样例）

### 5. 🗄️ SQLite WAL 模式（P2）

- StateStore 连接启用 WAL，改善 CLI 与 Dashboard 并发读写

## 验收

| 项 | 标准 |
|---|---|
| 参数化 | 单测覆盖替换/默认值/缺失报错；e2e 用 --set 跑通 |
| runs clean | dry-run 不删；真实删除五表行+目录；跳过非终态 |
| live 页 | TestClient 断言页面与轮询脚本存在 |
